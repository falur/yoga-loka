# Фикс: правило для ведущего слеша у native-функций

## Контекст

Пользователь попросил реализовать план: добавить правило PHP CS Fixer, которое ставит ведущий `\` у native/global PHP-функций везде, включая файлы без namespace, чтобы стиль не путался.

Учтены `docs/rules.md` и `docs/arch.md`.

## Что изменено

| # | Файл | Что изменено | Зачем |
|---|------|--------------|-------|
| 1 | `.php-cs-fixer.dist.php` | Добавлено правило `native_function_invocation` с `include: @internal, @compiler_optimized`, `scope: all`, `strict: true` | Единообразно добавлять ведущий `\` у native-функций во всех областях видимости |
| 2 | PHP-файлы проекта | `php-cs-fixer` применил новый стиль к текущему рабочему дереву | Вернуть/добавить ведущий `\` у native-функций после изменения правила |

## Тесты и проверки

| Команда | Результат | Заметки |
|---------|-----------|---------|
| `vendor/bin/php-cs-fixer fix --using-cache=no --config=.php-cs-fixer.dist.php` | ✓ | Применил форматирование текущего рабочего дерева |
| `vendor/bin/php-cs-fixer fix --dry-run --diff --using-cache=no --config=.php-cs-fixer.dist.php` | ✓ | Повторный прогон без diff |
| `php -l .php-cs-fixer.dist.php` | ✓ | Синтаксис конфига корректный |

Тесты приложения не запускались: поведение runtime-кода не менялось, правка касается только конфигурации форматтера и результата форматирования.
