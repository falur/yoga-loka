## Решения по optional

- **Принято: #1 (частично — документация + тест, без изменения кода).**
  Ревью прямо говорит «ничего менять в коде не обязательно» и предлагает зафиксировать
  существующее осознанное поведение в README рядом с сигнатурой `GetMediaUrl` и закрепить
  тестом. Это дёшево, не несёт риска регрессии и совпадает со стилем README модуля, где
  уже документируются подобные осознанные компромиссы. Альтернативный вариант (строить VO в
  начале `handle()` для единообразной валидации обоих путей) **не применялся**: он прямо
  противоречит явному решению плана (VO строится только в private-ветке, для public TTL
  игнорируется) и менял бы поведение.
  - В README в строку `GetMediaUrl` добавлено уточнение: для public-медиа `presignedTtlSeconds`
    игнорируется и не валидируется (прямой URL без срока), срок применяется и проверяется только
    для private.
  - Добавлен тест `testIgnoresInvalidTtlForPublicMedia`: public-медиа + заведомо невалидный TTL
    (`0`, вне диапазона `MediaPresignedTtl` `[1; 604_800]`) → успех, `presignGet` не зовётся.

- **Отклонено: #2.**
  Сам же раздел «Как исправить» после `rules-check` фиксирует, что текущее состояние двух
  локальных копий — **корректно по правилам проекта**, а вынос построения интервала в
  shared-утилиту ради двух строк прямо нарушил бы `rules.md` «Не плодить технические
  константы/обёртки». Хендлеры лежат в разных слоях CQRS (Command vs Query), общего базового
  класса нет. Оба предложенных варианта (привести стили к единому виду / сменить сигнатуру
  `buildUrl` на приём VO) — чистая стилистическая правка поверх уже корректного состояния:
  пользы для корректности нет, а изменение тёплого кода ради двух строк создаёт риск
  регрессии без выгоды. Отклонено как нецелесообразное.

- **Не правится: #3.**
  Это явное предупреждение о границах ревью (тип `docs`), а не дефект кода; ревью прямо
  указывает «кода менять не нужно». Решение зафиксировано: широкий Media-diff (S3-сервис,
  обработка изображений, пайплайн загрузки, правки `arch.md`/`rules.md`) выходит за рамки
  TTL-плана и должен быть закрыт собственным ревью своего плана
  (`docs/reviews/...media-upload-pipeline-uncommitted-draft.md`) до коммита всего рабочего
  дерева. В рамках текущего TTL-ревью никаких правок кода по этому пункту не требуется.

## Финальная проверка
- **Тесты:** `make test` — ✓ зелёные. 333 теста (было 332, +1 за счёт нового теста по #1),
  1132 ассерта (было 1129, +3). Deprecations/PHPUnit Notices — pre-existing baseline, на статус
  не влияют.
- **Линтер:** `make phpstan` — ✓ `No errors`.
- **Заметки:** запуск `vendor/bin/phpunit` напрямую с хоста не работает (не резолвится
  Cycle ORM / Spiral-контейнер без Docker-окружения), поэтому проверки прогнаны каноничными
  командами `make test` / `make phpstan` (Docker Compose) согласно `docs/rules.md`.
