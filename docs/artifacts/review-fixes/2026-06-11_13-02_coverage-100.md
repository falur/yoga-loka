## Решения по optional

- **Принято:**
  - **Сверка 1** — дешёвая документ-правка, снижает реальный риск: релиз-инженер/ревьюер, доверяя списку «единственные изменения продакшн-кода» в плане, мог пропустить третью правку (удалённый guard в `OpenApiPublishAssetsCommand`), которая меняет поведение на нестандартных итераторах. Решения 2 и 4 плана дополнены третьим пунктом с обоснованием «недостижимо + запрет мёртвого кода». Код не трогался — только файл плана.
  - **Сверка 2** — выполнено как обязательный финальный прогон скилла: `make qa` (cs + phpstan + test-coverage) даёт `Покрытие 100.00%` и exit 0. Заявленное журналом подтверждено фактическим прогоном перед коммитом.
  - **Замечание 1** — дёшево и без риска регрессии: добавлены короткие комментарии «привязка к приватному API фреймворка — чинить при апгрейде Spiral/Cycle» рядом с каждой рефлексией приватных свойств (`AbstractKernel::$finalizer`, `ExceptionHandler::$reporters`, `RelationMap::$innerRelations`, приватные свойства `LazyGhostMapper`, часть унаследована от базового Cycle Mapper). Тесты не переписывались, поведение не менялось. Делает точки техдолга находимыми при апгрейде версий.
  - **Замечание 2** — дёшево, улучшает читаемость и закрывает «ловушку на будущее»: расширен существующий комментарий перед хвостовым `throw` в `castField()` — явно зафиксирован инвариант «`supportsRule()` пропускает ровно четыре вида правил, три отсечены выше, значит здесь только `fromInt`; при добавлении нового вида правила хвост расширять синхронно». Логика не менялась, тест `ValueObjectCastDefensiveTest` уже покрывает ветку.
  - **Замечание 3** — усиливает контракт теста под требование плана (DSN строго из окружения) при нулевом риске: молчаливый фолбэк на литерал `redis://redis:6379/0` заменён явным `self::fail()` при отсутствии/пустом `REDIS_DSN`. `phpunit.xml:44` всегда задаёт `REDIS_DSN`, поэтому гейт остаётся зелёным; фолбэк больше не маскирует проблему конфигурации (мимо тестового Redis или против непредусмотренного инстанса).

- **Отклонено:**
  - **Замечание 4** (`ConfigMappingException` числовой сегмент через приватный хелпер) — ревью само рекомендует «оставить как есть, действий по коду не требуется»; комментарий в шапке теста уже есть. Единственная альтернатива из ревью — эскалировать и оставить строку непокрытой — прямо конфликтует с правилом проекта «100% покрытие» (`rules.md` «Тестирование», `arch.md` «Quality») и сломала бы гейт `make qa`. Правка либо ничего не меняет, либо создаёт регрессию покрытия → отклонено. Следующим ревьюерам: переоткрывать только при появлении публичного пути, через который сегмент достижим без рефлексии приватного метода.
