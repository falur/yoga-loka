# Фиксы по ревью: Рефакторинг Media URL-сервисов, RemoveMediaOriginal и config-independence (2-й круг)

Режим: `apply-optional`. Обязательных замечаний в ревью нет. Два optional-пункта «на усмотрение
автора»: №1 применён (точечная doc-only пометка), №2 отклонён с обоснованием.

## Применённые правки

| # | Замечание | Файлы | Тесты | Статус |
|---|-----------|-------|-------|--------|
| 1 | Полносетевой путь `FindMediaUrl` без runtime-потребителя нигде не помечен как осознанная заготовка | `app/src/Modules/Media/Application/Query/FindMediaUrl/FindMediaUrlHandler.php` (докблок) | — (правка только докблока; путь покрыт `FindMediaUrlHandlerTest`, поведение не менялось) | ✓ применено (optional) |
| 2 | N+1 разрешения аватаров в листинге профилей (`GetUserPublicProfilesHandler` → `UserPublicProfileAssembler`) | — | — | ✗ отклонено (optional, причина ниже) |

## Что именно сделано

- **№1 (optional, принято).** В докблок `FindMediaUrlHandler` добавлен абзац: полный набор ссылок
  (оригинал + все конверсии) сейчас не вызывается ни одним потребителем в `app/src` — узкий
  `FindMediaOriginalUrl` закрывает единственную текущую нужду (аватар профиля), а лента `Posts` строит
  оригинал из уже загруженной сущности; путь оставлен как foundational-API модуля `Media` под будущего
  потребителя (показ превью конверсий), симметрично пока не подключённой `RemoveMediaOriginal`, и
  покрыт модульным тестом. Это ровно рекомендованный ревью вариант «осознанно оставить + явная пометка
  рядом с описанием API, как сделано для `RemoveMediaOriginal`». Правка только документации, нулевой
  риск для прода, дополнительных тестов не требует. Отсутствие потребителя перед правкой подтверждено
  поиском: `FindMediaUrlHandler`/`FindMediaUrlQuery`/`getUrls(`/`findByIdWithConversions`/
  `MediaUrlsResult`/`MediaConversionUrlCollection`/`MediaConversionKind` ссылаются только внутри
  собственных папок модуля `Media` (+ тесты), внешнего runtime-вызова нет; `UserPublicProfileAssembler`
  диспатчит `FindMediaOriginalUrlQuery`.

## Решения по optional

- **Принято:**
  - **№1** — дешёвая (только докблок) пометка про отсутствие текущего runtime-потребителя, ровно тот
    вариант, что рекомендовало ревью, по образцу докблока `RemoveMediaOriginal`. Снимает
    непомеченность заметной новой поверхности без потребителя, нулевой риск.
- **Отклонено (чтобы следующие ревьюеры не поднимали заново без новых аргументов):**
  - **№2** — добавить в `Media` пакетный сценарий «URL оригиналов по набору медиа-идентификаторов» и
    собирать аватары листинга одним запросом. Отклонено: поведение pre-existing и диффом не ухудшено
    (число запросов на аватар относительно HEAD не меняется, регресса нет — это фиксирует и само
    ревью). Рекомендованный фикс — существенная новая поверхность (`Query` + `*Contract` + метод
    репозитория + DTO/коллекция), которую ревью само называет «отдельной задачей». Применение
    расширило бы scope текущего дифа вопреки «точечным изменениям» (AGENTS.md) и добавило бы ещё одну
    незадействованную поверхность — в противоречии с духом самого замечания №1. Аватар — одна дешёвая
    выборка по PK, набор ограничен размером страницы. Оставлено как отдельная задача на будущее; при
    реализации — feature-тест на выдачу профилей с проверкой числа запросов/корректности аватаров.
