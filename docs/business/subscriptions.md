# Подписки

## Назначение

Подписки позволяют пользователю следить за публикациями интересующих его людей и получать их новые публикации в своей ленте.

## Участники

- Подписчик — пользователь, который оформляет подписку.
- Автор — пользователь, на которого оформляется подписка.
- Система YogaLoka.

## Основные правила

- Все профили в первой версии открытые.
- Подписка оформляется сразу и не требует подтверждения автора.
- Пользователь не может подписаться сам на себя.
- Подписаться можно только на существующего доступного пользователя.
- Подписка направленная: подписка одного пользователя на другого не создаёт обратную подписку.
- Повторная подписка не создаёт вторую связь.
- Повторная подписка без предшествующей отписки не увеличивает число подписчиков и не создаёт повторное уведомление.
- Пользователь может в любой момент отписаться.
- Повторная отписка не считается ошибкой.

## Показатели и списки

Для каждого пользователя хранятся:

- список его подписчиков;
- список пользователей, на которых он подписан;
- количество подписчиков;
- количество подписок.

Списки подписчиков и подписок доступны:

- самому пользователю;
- другим пользователям из его публичного профиля.

Списки возвращаются от новых подписок к более старым.

Один пользователь не может появиться в одном списке несколько раз.

После подписки показатели обоих пользователей обновляются. После отписки они уменьшаются.

## Уведомление о новом подписчике

После успешной подписки автор получает:

- сохранённое уведомление внутри приложения;
- событие для показа всплывающего уведомления;
- push-уведомление, если этот вид push-уведомлений включён.

Уведомление содержит сведения о новом подписчике и позволяет перейти в его профиль.

Подписка на самого себя невозможна, поэтому собственное уведомление не создаётся.

Повторная подписка без отписки не создаёт новое уведомление.

Отписка не создаёт уведомление и не удаляет ранее созданное уведомление из истории.

Если пользователь отпишется, а затем снова подпишется, это считается новой подпиской и создаёт новое уведомление.

## Влияние на ленту

После подписки:

- новые публикации автора могут попадать в режим новых публикаций;
- публикации автора становятся доступны в режиме всех публикаций подписок;
- публикации, созданные до подписки, не считаются новыми.

После отписки публикации автора перестают показываться в обоих режимах ленты.

Подготовленная заранее лента может обновиться с небольшой задержкой, но после отписки публикации автора не должны возвращаться пользователю.

При повторной подписке ранее просмотренные публикации не становятся непросмотренными.

## Ограничения первой версии

В первую версию не входят:

- закрытые профили;
- запросы на подписку;
- подтверждение или отклонение подписки;
- ручное удаление отдельного подписчика владельцем профиля.

## Основные сценарии

### Подписка

1. Пользователь открывает чужой профиль.
2. Пользователь выбирает действие подписки.
3. Система проверяет, что пользователь не подписывается сам на себя.
4. Система создаёт подписку.
5. Показатели и списки пользователей обновляются.
6. Автор получает уведомление.
7. Новые публикации автора могут попадать в ленту подписчика.

### Повторная подписка

1. Пользователь повторно отправляет действие подписки.
2. Система обнаруживает существующую подписку.
3. Вторая связь и повторное уведомление не создаются.
4. Показатели не изменяются.

### Отписка

1. Пользователь выбирает действие отписки.
2. Система удаляет подписку.
3. Показатели и списки пользователей обновляются.
4. Публикации автора перестают показываться в ленте пользователя.
5. Уведомление об отписке не создаётся.

### Получение подписчиков

1. Пользователь открывает список подписчиков.
2. Система возвращает текущих подписчиков от новых к более старым.
3. Один пользователь возвращается только один раз.

### Получение подписок

1. Пользователь открывает список подписок.
2. Система возвращает пользователей, на которых оформлена подписка, от новых к более старым.
3. Один пользователь возвращается только один раз.

## Критерии готовности

- Пользователь может подписаться на другого доступного пользователя.
- Пользователь не может подписаться сам на себя.
- Подписка не требует подтверждения.
- Повторная подписка не создаёт дубликат.
- Пользователь может отписаться.
- Повторная отписка не считается ошибкой.
- Показатели подписчиков и подписок изменяются правильно.
- Списки подписчиков и подписок доступны из публичного профиля.
- Новый подписчик создаёт внутреннее, всплывающее и разрешённое push-уведомление.
- Отписка уведомление не создаёт.
- Подписка и отписка правильно влияют на ленту.
- Ранее просмотренные публикации не становятся новыми после повторной подписки.

## Расхождение с текущей реализацией

Подписки, списки подписчиков и подписок, соответствующие показатели и уведомление о новом подписчике пока не реализованы.
