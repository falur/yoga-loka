# План реализации

## Задача
Довести покрытие тестами `app/src` до **100% statements**. Сейчас **93.04% (2111/2269)**, непокрыто **158 строк в 29 файлах**. Гейт `make test-coverage` / `make qa` (`docker/test/assert-coverage.php runtime/coverage/clover.xml 100`) должен проходить.

Готово, когда `make test-coverage` печатает «Покрытие 100.00% соответствует порогу 100.00%», `make phpstan` зелёный, `make qa` проходит целиком.

## Контекст
- Правила проекта: **100% покрытие** + каждый роут integration-тест (`rules.md` «Тестирование», `arch.md` «Quality»). Порог понижать нельзя ([[test-coverage-gap]]). Новых HTTP-роутов задача не добавляет — правило «каждый роут integration-тест» уже соблюдено существующими тестами.
- Suite-ы: **Unit** (без контейнера), **Kernel** (Spiral kernel/контейнер, ORM), **Feature** (БД/Redis/S3/очередь). `phpunit.xml`: `CACHE_STORAGE=local`, `QUEUE_CONNECTION=sync`, `STORAGE_DEFAULT=s3-test`, `REDIS_DSN=redis://redis:6379/0`, `APP_ENV=testing`, `TOKENIZER_CACHE_TARGETS=true`. ## Принятые решения
1. **plan_size = normal** (подтверждено пользователем). 158 строк / 29 файлов / 3 suite не укладываются в short (≤2 фазы).
2. **Недостижимые в рантайме защитные guard'ы → минимальный рефактор под тест** (подтверждено пользователем), **без** понижения порога и **без** `@codeCoverageIgnore`. Конкретика после мета-ревью:
   - `ValueObjectCast.php:142` (`LogicException`, недостижим: `castField()` зовётся только для правил, прошедших `supportsRule()`, и одна из веток гарантированно совпадёт). Рефактор обязан оставить `make phpstan` (level max) зелёным: простое удаление `throw` оставит метод без финального return (`object|null`) → ошибка «missing return». Допустимая форма — реструктуризация (например `match(true)` или безопасный явный возврат), убирающая недостижимую ветвь и удовлетворяющая PHPStan. Если ни покрыть, ни безопасно отрефакторить нельзя — **эскалировать пользователю**.
   - `ConfigMapper.php:64,71` — расширить тип зависимости до интерфейса `Normalizer`, чтобы подставить fake; **PHPDoc-генерик не сужать** (`normalize()` обязан остаться `: mixed`), иначе PHPStan сочтёт `:63 is_array` always-true и guard станет мёртвым кодом → конфликт с «нет мёртвого кода».
   - `OpenApiPublishAssetsCommand.php:56-59` (зафиксировано пост-фактум по итогам исполнения и ревью) — удалить недостижимую защитную ветку `if (!$fileInfo instanceof \SplFileInfo) { continue; }` и сузить тип значения итератора аннотацией `/** @var \SplFileInfo $fileInfo */`. `RecursiveDirectoryIterator` с дефолтными флагами всегда отдаёт `SplFileInfo`, ветка недостижима, поэтому её сохранение конфликтует с правилом «нет мёртвого кода»; PHPStan остаётся зелёным за счёт аннотации. Это третья (и последняя) точка изменения продакшн-кода в задаче.
3. **Размещение тестов по suite** (autonomous, по конвенциям): VO / typecast / `ValueObjectCast` / `LazyGhostReflectionRegistry` / `ConfigMapper` / `ConfigMappingException` / `SystemOutboxRelaySleeper` → Unit; `LazyGhostMapper` (discriminator-ветки — Unit с поддельной схемой; happy-path extract — Kernel через Media) / `LazyGhostEntityFactory` / `ExceptionHandlerBootloader` → Kernel; `OutboxRelay` / `StoredOutboxEvent` reclaim / `OutboxQueueStatusInterceptor` / `DeleteMediaHandler` / `OpenApiGenerateCommand` / `OpenApiPublishAssetsCommand` / `RedisCacheStorage` → Feature.
4. **Без новых зависимостей, изменений БД, API, очередей.** Единственные изменения продакшн-кода — точечные test-enabling рефакторы из решения 2: `ValueObjectCast:142`, тип `Normalizer` в `ConfigMapper` и удаление недостижимой guard-ветки в `OpenApiPublishAssetsCommand:56-59`. Все три — удаление недостижимого/мёртвого кода или расширение типа зависимости ради подстановки fake; поведение на штатных входах не меняется, PHPStan level max остаётся зелёным.

## Целевой алгоритм
Для каждого непокрытого файла: определить характер непокрытой ветки (валидация-throw / equals / jsonSerialize / typecast-ветка / ORM-сценарий / защитный guard) → выбрать suite по решению 3 → расширить существующий тест или создать новый с crafted-входами, добивающими **каждую** указанную строку → прогнать suite фазы и проверить покрытие файла (targeted PCOV-прогон) → убедиться, что строки файла закрыты. Для недостижимых guard'ов из решения 2 — минимальный рефактор + тест. В конце — полный `make test-coverage` (=100%) и `make phpstan`.

## Тесты
Стратегия **after_each_phase**: каждая фаза заканчивается прогоном своего suite (`make test-unit` / `test-kernel` / `test-feature`) до зелёного **плюс** точечной проверкой покрытия файлов фазы. paratest не умеет `--coverage-text`, поэтому точечная проверка — отдельный прогон в тест-контейнере: `XDEBUG_MODE=off php -d pcov.enabled=1 -d pcov.directory=app/src vendor/bin/phpunit --testsuite <Suite> --filter <NewTest> --coverage-clover <tmp.xml>` и парсинг непокрытых строк целевого файла (как делает основной гейт). Авторитетная финальная проверка — полный `make test-coverage` (=100%) + `make phpstan` в фазе 6. Новые тесты следуют конвенциям: Unit — без контейнера; Kernel/Feature — `Tests\TestCase` + `getContainer()`/`runCommand()`; данные через ORM или Cycle Query Builder (без сырого SQL).
