## Решения по optional

### Принято
- **№1 (README):** добавил в раздел «Транзакционная дисциплина S3» явное допущение — набор
  `conversions` фиксируется один раз в `CompleteMediaUpload` и едет в outbox, поэтому стабилен;
  повторная обработка перезаписывает объекты по детерминированным ключам и не размножает их, но
  при гипотетическом повторе с другим набором ранее залитые конверсии стали бы осиротевшими.
  Ревью прямо предлагает «задокументировать в README». Дёшево, без кода, без риска.
- **№4 (код + тест):** перенёс чтение оригинала (`getObjectContents`) внутрь ветки с непустым
  набором конверсий — для видео/без конверсий оригинал больше не качается в память зря,
  выполняется только server-side `copyObject`. Это конкретная безопасная рекомендация ревью.
  Потоковое чтение/temp-файл — вне scope (gold-plating), не делал. Тест
  `testProcessesMediaWithoutConversionsMovesOriginalOnly` усилен: `getObjectContents` теперь
  ассертится `never` (раньше был сконфигурирован неиспользуемый stub — после правки он бы давал
  PHPUnit Notice). README дополнил одной фразой про условное чтение оригинала.
- **№8 (README):** зафиксировал trade-off — для multipart-ветки внешние S3-операции
  (`completeMultipartUpload`, `headObject`) идут под открытой транзакцией БД; это осознанный
  компромисс (повтор complete идемпотентен, транзакция короткая), при проблемах с длительными
  транзакциями сборку multipart/HEAD стоит вынести за транзакцию по образцу `ProcessMediaHandler`.
  Ревью для текущего scope рекомендует именно «зафиксировать trade-off в README», не рефакторить.
- **№10 (код):** понизил `logger->info('Медиа готово.')` до `logger->debug`. Это был
  единственный INFO в бизнес-коде `app/src`; рутинное per-media завершение по правилу
  `rules.md:84` ближе к DEBUG (INFO — для ключевых бизнес-событий), соседние хендлеры пишут
  `debug`. Низкий риск: ни один тест не ассертит уровень лога. План предписывал INFO, но это
  формальное расхождение с правилом, и выравнивание по правилу — улучшение без побочных эффектов.

### Отклонено
- **№2** — `recordPermanentProcessingError` существует в `HEAD` (закоммичен до этого diff;
  diff `Media.php` добавляет только `markReadyMovedTo`/`isReady`), нигде не вызывается и не
  покрыт. Само ревью оставило пункт optional именно потому, что «удаление дубликата корректнее
  провести отдельным решением, не маскируя в media-фиче». Правка расширила бы scope на чужой
  пред-существующий код. Отклонено как выход за scope; чистить дубликат — отдельной задачей.
- **№3** — guard расширен до `uploaded`/`processing`/`processingFailed` осознанно (ретрай после
  транзиентной ошибки приходит из `processingFailed`; строгий guard вечно ронял бы ретрай в 500).
  Ревью: «ничего не менять в коде»; причина уже зафиксирована в журнале и в docblock
  `markReadyMovedTo`. Менять нечего.
- **№5** — кэширование `S3Client` по серверу. Практический эффект мал (конструктор дёшев против
  сетевого вызова), а для кэша пришлось бы делать `readonly`-провайдер не-readonly или вводить
  контейнерный кэш — структурное изменение с риском регрессии ради микро-выгоды на горячем пути.
  Gold-plating относительно пользы. Ревью: «отдельный тест не нужен», эффект «мал».
- **№6** — отсутствие ретрая `headObject` для multipart. Осознанное сужение низкого риска: MinIO
  даёт read-after-write consistency. Ревью: «Для текущего scope можно оставить как есть»;
  ретрай добавлять «только при реальной флаки». Преждевременно.
- **№7** — переименование `ImagickMediaImageProcessor` → `InterventionMediaImageProcessor`.
  Имя задано планом; переименование тронет биндинг в `MediaBootloader` + unit-тест ради чистой
  косметики. Docblock класса уже поясняет поддержку gd. Ревью: «отдельное решение».
- **№9** — enum драйвера вместо `string`+`match`. План сознательно выбрал `string` «чтобы Shared
  не зависел от модульного enum» (журнал, фаза 2; подтверждено в plan-polish итерации 2). Ревью
  прямо: «Решение конфликтует с явным выбором плана — это отдельное решение». Не ломаю осознанное
  решение плана ради формального соответствия `rules.md:30`; единственная throw-ветка покрыта тестом.
