# Фиксы по ревью: Избавиться от deprecated в тестах (PHPUnit 13 + PHP 8.5)

Режим: `apply-optional`. В ревью нет пунктов «Править обязательно» — только «На усмотрение
автора». По каждому optional-пункту решение принято автономно.

Важный нюанс зафиксирован и соблюдён: реализация сознательно отклонилась от плана (использован
`createStub` + `willReturnMap` вместо `expects(any)` + `with()`), потому что подход плана на
PHPUnit 13.1.8 не убирает деприкейшен, а заменяет его новым про `any()`. Это отклонение
подтверждено пользователем в журнале выполнения и **не откатывалось** — фиксы улучшают текущий
подход, а не возвращают отклонённый планом вариант.

## Решения по optional

### Принято
- **Замечание 3 (инлайн `$bytes`).** Дёшево, ровно по правилу `docs/rules.md` «Инлайн
  одноразовых переменных», поведение не меняется. Свёрнуто в `return (string) \ob_get_clean();`
  в обеих фикстурах.
- **Замечание 2 (неверный факт в журнале).** Артефакт, на который будут опираться будущие
  правки. Формулировка «`willReturnMap` вернёт `null`» заменена на корректную: при неверной
  секции стаб вернёт `[]` (дефолт по типу возврата `getConfig(): array`), а маппинг падает
  из-за обязательных полей DTO; проверка секции теперь косвенная, а не явная.
- **Проблема сверки #1 + Замечание 1 (закрепить решение и его caveat).** Ревью предлагало для
  «Проблемы сверки #1» именно фиксацию решения (правка кода не требуется — выбор согласован), а
  для Замечания 1 — либо усиление, либо «оставить осознанно». Обе рекомендации закрыты одной
  низкозатратной правкой: в `docs/rules.md` (раздел «Тестирование») добавлено правило — в
  PHPUnit 13 для дублёров-данных использовать `createStub` + `willReturn*`/`willReturnMap`
  (не `expects(any)`, который сам деприкейтнут), с явным caveat: `willReturnMap` при несовпавшем
  аргументе возвращает дефолт по типу (`[]` для `: array`), поэтому стаб сам секцию не проверяет;
  для конфига со всеми опциональными полями нужен отдельный позитивный тест на ожидаемую секцию.
  Это переводит решение из разового исключения в осознанное правило проекта и предупреждает
  следующего автора о точке регрессии.

### Отклонено
- **Замечание 1 — правка кода (добавить `willReturnCallback`, проверяющий секцию, или отдельный
  негативный тест в 5 helper-методов).** Отклонено по причинам:
  1. Ревью само классифицирует «оставить как есть, но осознанно» как валидный вариант: текущие 5
     конфигов имеют обязательные поля, поэтому «не та секция» уже даёт красный исход. Риск
     теоретический — конфига со всеми опциональными полями сейчас нет.
  2. `willReturnCallback`, бросающий при несовпадении аргумента, превращает чистый стаб
     (`createStub`) обратно в дублёр с assertion-поведением — это ровно то разделение
     stub/mock, ради которого PHPUnit 13 ввёл split и на которое опирается выбранное решение
     задачи. Добавлять это в 5 helper-методов ради гипотетического будущего конфига —
     расширение scope задачи «убрать deprecated».
  3. Остаточный риск дешевле и долговечнее закрыт правилом в `docs/rules.md` (см. «Принято»):
     будущий автора, добавляя all-optional конфиг, получит явное указание завести позитивный
     тест на секцию.
