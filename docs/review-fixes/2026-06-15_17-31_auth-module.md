### Что сделано по замечанию 1 (выбран Вариант Б — каноничный для 3.1)

Реализован переносимый, version-aware способ выражения обнуляемости в пакете
`spiral-openapi`, а не точечная подмена ключа:

- Заведён `GianTiaga\SpiralOpenApi\Schema\NullableSchema` — единая точка, которая по
  объявленной версии документа (`OpenApiGeneratorConfig::openApiVersion`) выбирает форму:
  - **OpenAPI 3.1** (текущий дефолт `3.1.0`): скаляр и массив → `type: [<type>, "null"]`
    (с сохранением `items`); `$ref` и составные схемы → `oneOf: [<схема>, {type: "null"}]`.
    Ключ `nullable` не эмитится.
  - **OpenAPI 3.0** (на случай понижения версии в конфиге): скаляр/массив → `nullable: true`;
    `$ref` оборачивается в `allOf: [<$ref>]` + `nullable: true`, чтобы `nullable` не оказался
    игнорируемым соседом `$ref`.
- `SchemaBuilder::schemaForProperty` теперь делегирует обнуляемость в `NullableSchema`
  (покрывает скаляры, `$ref` и nullable-списки одной веткой).
- `SpecBuilder` прокидывает `NullableSchema` (созданный из `config->openApiVersion`) во все
  места, где раньше инлайнился `nullable: true`: `ErrorResponse.code` и `meta.nextCursor`
  (cursor-пагинация).
- Спецификация перегенерирована командой `openapi:generate`. В `public/openapi/openapi.yml`
  при `openapi: 3.1.0`: `ErrorResponse.code` → `type: [integer, "null"]`,
  `VerifyResultResource.tokens` → `oneOf: [{$ref: TokenPairResource}, {type: "null"}]`,
  `VerifyResultResource.registrationTicket` → `type: [string, "null"]`. Ни одного ключа
  `nullable` в документе не осталось.

### Тесты под выбранный способ

- Добавлен `NullableSchemaTest`: 5 кейсов покрывают обе версии и все формы (скаляр-union,
  массив-union с `items`, `oneOf` для ссылки в 3.1; `nullable` для скаляра и `allOf` для
  ссылки в 3.0). Это закрывает 100% покрытие новой ветки 3.0, которая в продакшн-конфиге не
  используется.
- `OpenApiGeneratorTest::assertUserResourceNullableSchema` переписан: вместо «есть ключ
  `nullable`» проверяет фактический 3.1-способ — `type: [string, "null"]` для скаляра,
  `type: [array, "null"]` c `items` для списка, `oneOf` для `$ref`, и явно утверждает
  отсутствие ключа `nullable` и соседства `nullable` с `$ref`.
- App-level `AuthOpenApiGenerationTest::testVerifyResultResourceSchemaMarksNullableFields`
  (привязан к фазе 7 плана «корректность схемы VerifyResultResource с nullable-полями»)
  обновлён: проверяет `openapi: 3.1.0` и 3.1-форму `tokens`/`registrationTicket`, отсутствие
  ключа `nullable`.

## Решения по optional

- **Принято:** только обязательный пункт 1 (в ревью optional-пунктов нет — `На усмотрение
  автора: нет`).
- **Отклонено:** ничего нового. Ранее осознанно отклонённые пункты (контракт рендерера
  `spiral-api-errors` `array<string,string>`; полное выравнивание `RegisterFilter` под
  нормализацию VO) не возвращены — по ним нет новых аргументов; повторно их поднимать не
  следует.
