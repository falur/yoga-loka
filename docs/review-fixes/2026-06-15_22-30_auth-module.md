### Детали по замечанию 2
- Порт `LoginCodeMailerContract::send(string $email, string $subject, string $body): void` лежит в `Auth/Application/Contract` — следует тому же паттерну, что уже трижды применён в модуле (`SecretHasherContract`, `TokenGeneratorContract`, `AuthTokenStorageContract`).
- Адаптер `SpiralLoginCodeMailer` (`Auth/Infrastructure/Mail`) инжектит `Spiral\Mailer\MailerInterface`, собирает `Message` с view `login-code` и вызывает `send()`. Это единственное место в `app/src`, где остался импорт `Spiral\Mailer` (проверено grep).
- Логика выбора локали (`resolveLocale`) и переводы темы/тела остались в Application-хендлере; в Infrastructure ушло только построение `Message` и вызов отправки — ровно как предлагало ревью.
- Поведение отправки сохранено: те же view, адрес, тема и тело письма. Прежние ассерты на shape `Message` перенесены в новый тест адаптера; сценарные тесты Application теперь проверяют захваченные email/subject/body через дублёр контракта.
- Биндинг `LoginCodeMailerContract::class => SpiralLoginCodeMailer::class` добавлен в `AuthBootloader::BINDINGS` рядом с тремя существующими.

## Решения по optional
- **Принято:** нет optional-замечаний, помеченных к применению.
- **Отклонено:** замечание 1 (узкий vendor-PHPDoc рендерера `spiral-api-errors`) — отклонено повторно с прежней причиной. Корень в чужом `ErrorsRendererInterface`, PHPDoc которого пакет не контролирует и по которому PHPStan сужает тип; расхождение локализовано, обработано защитно (`firstMessage` берёт первый элемент или пустую строку), задокументировано рядом с кодом и покрыто тестами (строка, список, пустой список). Новых фактов в пятом круге нет — пункт ранее уже осознанно отклонён командой. Расширять контракт не требуется. Прочие ранее осознанно отклонённые пункты (полное выравнивание `RegisterFilter` с нормализацией VO) не пересматривались.
