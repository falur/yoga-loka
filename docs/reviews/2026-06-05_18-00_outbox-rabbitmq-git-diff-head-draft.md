# Ревью: Outbox/RabbitMQ

## Оценка

**86/100.** Базовая реализация выстроена и покрыта тестами, но два больших риска остаются: обработка повреждённых записей outbox и глобальная замена маппера ORM на `LazyGhostMapper`.

## Проблемы сверки с планом

1. Есть соответствие общему плану по введению outbox-цепочки, relay, очереди и сериализации.
2. Используется новый отладочный путь через `OutboxDebugLogMessage` и тестовый артефакт для него.
3. Не покрыты риски глобального влияния `Cycle`-конфигурации на весь домен.

## Замечания

### 1. Неполная обработка `TypecastException` в `findPendingForRelay`

`OutboxEventRepository::findPendingForRelay` ловит любые `TypecastException`, но в обработке ошибок ориентируется только на поле `type`, и при падении по другому полю (например, `available_at`, `id`) запись может продолжать мешать циклу, повторно подхватываться как pending и создавать нестабильное поведение relay.

- **Статус:** частично
- **Где:** `app/src/Modules/Outbox/Repository/OutboxEventRepository.php`
- **Подтверждение:** метод фильтрует ошибочные записи через `markInvalidOutboxTypesAsFailed()`, где проверяется только тип.
- **Что лучше:** в блоке `catch` явно диагностировать источник `TypecastException`, для конкретной причины помечать запись failed и оставлять диагностическое сообщение; не ограничиваться только `type`.
- **Тест:** добавить сценарий, где испорчено не поле `type`, и проверить финальное состояние failed + стабильный выход из цикла.

### 2. `LazyGhostMapper` включён глобально для всех сущностей через `SchemaInterface::MAPPER`

Переход на кастомный маппер полезен для outbox, но глобальное включение меняет поведение всей ORM. Любая ошибка в фабрике/рефлексии или типизации отразится не только на outbox-модуле.

- **Статус:** на обсуждении
- **Где:** `app/config/cycle.php`, `app/src/Shared/Infrastructure/Cycle/LazyGhostMapper.php`
- **Подтверждение:** существующие новые тесты акцентированы на `media` и сам модуль outbox, но не проверяют влияние на все типы сущностей.
- **Что лучше:** ограничить применение на уровне схем, где это нужно, или добавить широкие регрессионные тесты по другим модулям (relations, readonly-поля, сложные value objects) до merge.
