(`docs/review-fixes/2026-06-10_17-05_media-presigned-ttl-from-code.md`). Целевое состояние плана

«удаления» подтверждается журналом выполнения и поиском по дереву, а не diff-строкой против HEAD.

## Замечания

### 1. README в схеме «Поток загрузки» не повторяет оговорку про игнорирование TTL для public

В README модуля две части описывают `GetMediaUrl`. В таблице публичного API (строка 25) аккуратно
сказано, что для public-медиа `presignedTtlSeconds` игнорируется и не валидируется — это и есть фикс
прошлой итерации. В схеме «Поток загрузки» шаг 6 описывает GetMediaUrl как «public → прямой URL ...;
private → presignGet (TTL из presignedTtlSeconds запроса)». Здесь нет противоречия с таблицей:
парентеза «(TTL из presignedTtlSeconds запроса)» синтаксически привязана к ветке `private →
presignGet` (после `;`), а public уже показан как «прямой URL» без срока. То есть схема согласована с
таблицей и не утверждает, что TTL применяется к public.

Замечание чисто документационное и низкое по весу: дефект не в неверности, а в неполноте — схема
потока не повторяет явную оговорку «для public срок не применяется и не валидируется», которая есть в
таблице (строка 25). Читатель, который смотрит только на схему, увидит верную, но менее подробную
картину. Реальных потребителей ещё нет, на поведение это не влияет. Для симметрии с таблицей оговорку
про public стоит добавить и в шаг 6, но это полировка текста на усмотрение автора, не обязательная
правка.

Технические детали:

- **Тип:** `docs`
- **Рекомендация:** `на усмотрение автора`
- **Где:** `app/src/Modules/Media/README.md:59-61` — шаг 6 схемы «Поток загрузки»; сравнить со строкой
  25 (таблица публичного API), где оговорка про public уже есть.
- **Что подтверждает проблему:** строка 60 `(TTL из presignedTtlSeconds запроса)` привязана к
  private-ветке шага 6 и сама по себе верна, но шаг 6 не повторяет оговорку «для public срок не
  применяется и не валидируется», которая явно есть в строке 25 и в разделе «Инфраструктура и конфиг»
  (строки 130-133). То есть документ корректен, но в схеме потока менее подробен про public, чем в
  таблице API.
- **Как исправить:** в строке 60 добавить короткую оговорку, что `presignedTtlSeconds` применяется
  только к private-ветке, например «private → presignGet (TTL из `presignedTtlSeconds`; для public
  срок не применяется)». Кода менять не нужно.
- **Тесты:** не требуется — поведение уже покрыто `testIgnoresInvalidTtlForPublicMedia` и
  `testReturnsDirectPublicUrlForPublicMedia`; правка только текстовая.

## Ранее разобранные пункты (не повторяю как новые проблемы)

Эти пункты осознанно закрыты на прошлой итерации и без новых аргументов повторно не выносятся:

- **Невалидный TTL для public молча проходит (прошлый #1)** — закрыт: README документирует поведение
  (строка 25), добавлен тест `testIgnoresInvalidTtlForPublicMedia` (public + TTL=0 → успех,
  `presignGet` не зовётся). Код по плану не менялся. Подтверждено в коде и тестах.
- **Дублирование «секунды → DateTimeImmutable» (прошлый #2)** — отклонён осознанно: две локальные
  копии (`RequestMediaUploadHandler::expiresIn()` и инлайн в `GetMediaUrlHandler::buildUrl()`)
  корректны по `rules.md` «Не плодить технические константы/обёртки». Уточнение причины отклонения
  (по мета-ревью): технически дедуп возможен — общий дом был бы методом на VO `MediaPresignedTtl`
  (например, `expiresFromNow(): \DateTimeImmutable`), которым пользовались бы обе presigned-точки.
  Но выигрыш марджинальный: staging-путь (`RequestMediaUploadHandler::expiresIn($stagingTtlSeconds)`)
  работает с сырым int из конфига, а не с `MediaPresignedTtl`, и всё равно сохранил бы свой helper —
  то есть `expiresIn()` не исчезает, а ради одной строки в `buildUrl` заводить метод на VO
  нецелесообразно. Остаётся optional, форсировать не нужно.
- **Широкий diff вне TTL-плана (прошлый #3)** — предупреждение о границах ревью, не дефект кода.
  Рабочее дерево содержит весь модуль Media (S3-сервис, обработка изображений, пайплайн загрузки),
  он закрывается своим ревью (`docs/reviews/...media-upload-pipeline...`). Для TTL-ревью кода менять
  не нужно.

Дополнительно проверено и подтверждено корректным (не выношу как проблемы):

- `AbstractIntegerValue::supports()` добавлен и используется в production
  (`CompleteMediaUploadHandler:114-115` для `MediaPixelDimension`) — это часть пайплайна загрузки, не
  мёртвый код. Для самого `MediaPresignedTtl` `supports()` в production не вызывается, что
  соответствует решению плана «422/`supports()` на границе не вводим — нет пользовательского ввода».
- В конфиге/env/phpunit нет осиротевшего `presignedTtlSeconds`/`MEDIA_PRESIGNED_TTL_SECONDS` (поиск
  по всему дереву чист); все ссылки `presignedTtlSeconds` — намеренные (Query DTO, оба хендлера,
  тесты, README).
