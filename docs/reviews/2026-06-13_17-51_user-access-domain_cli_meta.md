# Кросс-CLI мета-ревью (codex, gpt-5.5) — итог

Соседний CLI прочитал ревью, target-код, план, rules.md, arch.md и research. Дистиллированный вердикт (полный лог прогона не сохранён — содержал сборочный шум):

- `~` Замечание 1 (phpstan-ignore): ignore ради `Normalizer::FORM_C` обоснован (native `$string` vs polyfill `$s`), но scoped по двум *файлам*, а не двум строкам. `reportUnmatchedIgnoredErrors` защищает только от полного несовпадения, не от лишних совпадений: будущий позиционный вызов с 2+ аргументами в этих файлах тоже погасится. → внесено в Замечание 1.
- `−` Замечание 2 (`isUuidV7()`): снять трактовку «риск размывания VO» — в проекте уже есть принятый публичный предикат `AbstractIntegerValue::supports()` для проверки на границе до создания VO; `isUuidV7()` в том же паттерне, одно внешнее использование проблему не доказывает. → Замечание 2 переформулировано в неконсистентность имени.
- `+` `UserBio`: regex `/(?!\n)\p{Cc}/u` корректен сам по себе, но при невалидном UTF-8 `preg_match(..., /u)` возвращает `false`, а проверка бросает только на `=== 1` → битая UTF-8 строка проходит как bio. Нужен тест на `"\xC3\x28"` и обработка `false`. → внесено как Замечание 3 (подтверждено исполнением PHP).
- отклонено: порядок `trim()` перед regex (`"\tvalid"` → `"valid"`) — отклонено как не-дефект (обрезка краевых управляющих символов корректна и желательна).
- `~` Смягчить «`UserBio` расширен без побочных эффектов» — внесено в «Оценку».
- `?` `make phpstan` у codex не запустился (доступ к Docker API). Прогон выполнен в основной мета-проверке локально (level max, No errors).
