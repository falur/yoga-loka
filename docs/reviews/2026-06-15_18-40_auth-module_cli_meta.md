# Кросс-CLI мета-ревью (codex) — 2026-06-15_18-40_auth-module

Соседний CLI: `codex exec` (codex-cli 0.139.0). Цель — глубокая проверка ревью по плану,
правилам, архитектуре и коду. Результат (формат +/−/~/?):

~ **Замечание 1** оставить, но переформулировать: рассинхрон не «интерфейса пакета», а
vendor-контракта `Spiral\Filters\ErrorsRendererInterface` и фактического поведения
`spiral-packages/symfony-validator`, где ошибки поля складываются списком. Исправление через
изменение интерфейса локального пакета невозможно; лучше описать как локальную адаптацию к
узкому vendor PHPDoc.

~ **Замечание 2** оставить, но сузить формулировку: проблема подтверждается для `nickname` с
пробелами по краям и для `name`, где сырая длина больше 100, а после `trim`/схлопывания
пробелов укладывается в лимит. Не писать про «multi-space name» как про проблему формата:
regex фильтра пробелы допускает (проблема в `Length` по сырой длине, не в regex).

− **Убрать замечание 3**: фактически неверно. В `tests/Feature/Modules/Auth/Http/AuthHttpTest.php`
метод `http()` каждый раз ставит новый `REMOTE_ADDR` через `uniqueClientIp()`, ключ rate limit —
`sha256(ip|path)`. Между тест-кейсами счётчик не делится; внутри rate-limit-тестов один `$http`
переиспользуется намеренно.

+ **Добавить optional по `packages/spiral-openapi`**: исправление nullable-union неполное для
nullable-списков. В `SchemaBuilder::schemaForProperty()` (`:56-58`) ветка `listItemType !== null`
сразу возвращает array-схему и не добавляет `nullable`, хотя `PhpAstParser` уже умеет пометить
свойство nullable. Нужен пакетный тест на `/** @var list<T> */ public array|null $items = null`
и применение nullable в этой ветке.
